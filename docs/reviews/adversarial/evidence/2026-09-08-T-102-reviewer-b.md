### P1 — CAPTURE_ONLY가 target 전체의 강제 안전 경계가 아님

- 위치:
  - `firmware/communicator/stm32/interface/canview_build_mode.h:13-25`

  - `tools/check_stm32_core.py:19-31`
- 실패 시나리오:
  1. 새 STM32 source가 `canview_build_mode.h`를 include하지 않고 FDCAN register/LL API 또는 다른 TX 경로를 사용한다.
  2. 또는 header include 후 `#undef CANVIEW_STM_TX_PERMIT`/`#undef CANVIEW_STM_CONTROL_CAPABILITIES`로 macro를 재정의한다.
  3. CMake는 문자열 `CAPTURE_ONLY`만 확인하고, symbol gate는 두 개의 HAL TX symbol만 금지한다.
- 영향:
  - 현재 source에 TX 구현이 없다는 사실과 별개로, 이후 target composition에서 차량 TX가 들어와도 compile-time CAPTURE_ONLY 계약이 자동으로 차단되지 않는다.
  - 직접 FDCAN register 접근, LL 계열, 다른 HAL/외부 library는 현재 symbol 목록을 통과할 수 있다.
  - 외부 TX gate가 아직 실물 검증되지 않은 상태에서 safety boundary가 우회될 수 있다.
- 권고:
  - mode/capability를 일반 재정의 가능한 macro가 아닌 generated immutable contract와 link-time sentinel로 구성한다.
  - 모든 STM32 target source에 mode header/include 강제를 적용한다.
  - FDCAN TX register/LL/HAL 전체 금지 목록과 hardware TX-gate symbol 검사를 추가한다.
  - override compile negative fixture와 실제 target mutation test를 추가한다.
