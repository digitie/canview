### A-P2-03 — hardware FIFO 손실과 invalid FIFO 계약이 신뢰할 수 있는 loss/fault로 반영되지 않음

- 위치: [platform/stm32g474/fdcan_capture.c:370](F:/dev/canview/firmware/communicator/stm32/platform/stm32g474/fdcan_capture.c:370)
- 관련 처리: 같은 파일 377–380행, 392–396행, 504–512행, 580–594행.
- 실패 시나리오:
  - hardware FIFO overflow는 발생하지만 software raw ring은 가득 차지 않은 경우.
  - FIFO fill level 또는 get index가 계약 범위를 벗어난 경우.
- 영향:
  - `raw_drops`는 software ring full에서만 증가하므로 hardware loss는 exact drop 보고에 포함되지 않는다. RF0L은 `last_error`에 남을 수 있지만 loss 수의 불확실성은 구분되지 않는다.
  - invalid FIFO 분기는 IR의 RF0L에 write한 뒤 끝나며 software loss/fault를 latch하지 않는다. 원래 IRQ snapshot에 RF0L이 없었다면 문서가 약속한 FIFO loss 기록도 남지 않는다.
- 권고: hardware overflow를 별도의 overflow event·최소 손실량·정확한 수량 불명 상태로 표현한다. invalid FIFO 계약은 software fault로 명시적으로 latch하고 안전한 peripheral 격리 경로를 둔다.
- 근거 유형: counter와 error propagation 소스 추적. hardware overflow 실측은 미실행.

### A-P2-04 — filter가 거부한 record는 worker 처리 budget에 포함되지 않음

- 영향: loop 종료 기준인 `result.count`가 증가하지 않는다. 단일 호출의 처리량이 batch 최대 12개로 제한되지 않으며, producer가 보충하는 조건에서는 고정 상한이 없다. observer 처리 때문에 다른 worker와 watchdog vote가 지연될 수 있다.

## 공격했으나 별도 finding을 만들지 않은 범위

| 공격 범위 | 확인 내용과 한계 |
|---|---|
| module ring full | 64-slot 검사 후 drop을 증가시키며 timestamp state를 변경하지 않는다. |
| software raw ring full | slot overwrite 대신 saturating drop을 증가시킨다. uint8 index와 16-slot 용량의 distance 계약은 소스상 일관된다. |
| frame memory bounds | decoder는 4-word snapshot과 최대 8-byte data만 접근한다. ID/DLC/flags/padding 검사가 있다. |
| FD/BRS/RTR | FD는 unsupported, BRS-only·초과 DLC는 malformed로 분리한다. RTR data를 zero로 정규화한다. 실제 peripheral의 FD 관찰 능력은 확인하지 않았다. |
| invalid profile | disabled field 오염, unknown PHY, timing 범위, SJW/segment 관계, CAN3 PHY/125 kbit/s 제한을 검사한다. |
| generated pin 계약 | 현재 RX/TX request pin은 adapter compile-time 조건과 일치한다. package/symbol 및 전기적 적합성 승인은 아니다. |
| ISR 책임 | FIFO 최대 3개 snapshot, heap·로그·callback 없음. worker callback 호출 수는 raw service에서 채널별 최대 16회다. IRQ acknowledge 문제는 별도 finding으로 기록했다. |
| callback lifetime/reentry | platform sink는 stack-local snapshot을 받으므로 정적 context·동기 소비 계약이 필요하다. 문서가 금지한 platform sink 재진입을 정상 사용으로 가정하지 않았다. module filter 재진입 손실은 별도 기록했다. |
| partial start failure | instance 실패 시 이전 started instance를 disable하고 safe output을 다시 적용한다. 실제 register timeout·GPIO 실패 주입은 하지 않았다. |
| passive/bus-off | `observe()`가 passive/bus-off를 no-data로 덮어쓰지 않는다. adapter에 bus-off TX 재개 API는 없다. |
| TX/control authority | 검토한 신규 경로에 TX descriptor/request API, raw replay, control lease가 없다. TX request pin은 high 출력으로 설정한다. |
| watchdog/reset | 기존 core의 PRIMASK 복원, fault latch, reset handler와 watchdog owner를 확인했다. capture callback에서 watchdog을 feed하지 않는다. |
| Bridge 격리 | 변경 파일 목록에 Bridge 제어 경로 변경이 없다. STM32 capture output이 Bridge에 TX 권한을 부여하는 신규 연결도 없다. |
| inventory 포화 | 고정 table full은 inventory drop으로 처리하며 capture record 자체를 중단하지 않는다. |

exec(compile(source, candidate + ":" + path, "exec"), namespace)

class MemoryEvidence:

        self.payload = payload

        return self.payload

for label, payload in [
