**Finding A-01 — P1 / OPEN: deadline을 넘긴 성공이 이전 진척을 덮어쓰고 watchdog 갱신을 허용함**

위치: [scheduler.c:84](F:/dev/canview/firmware/communicator/stm32/module/scheduler.c:84), 같은 파일 99–114, 157–173행. 행 번호는 위 candidate 기준입니다.

`run_due()`는 모든 worker의 deadline을 step 시작 시각인 `now_ms`로 검사합니다. 앞선 worker 또는 현재 callback에서 시간이 경과해 deadline을 넘겨도, 반환값이 `OK`이면 이전 `last_progress_ms`를 먼저 `now_ms`로 덮어씁니다. 마지막 freshness 검사는 이미 덮어쓴 값을 사용하므로 발생했던 deadline miss를 발견하지 못합니다.

독립 재현은 candidate의 기존 fixture helper와 실제 scheduler library를 그대로 사용했습니다.

1. 선택 worker와 필수 worker를 순서대로 등록합니다. 필수 worker의 period/deadline/budget은 `1ms/10ms/1000us`입니다.
2. `step(0)`에서 두 worker가 즉시 성공합니다.
3. `step(10)`에서는 각각 1000µs 실행 후 성공하도록 합니다.
4. 필수 worker는 실제 11ms에 시작하여 12ms에 완료하지만 결과는 다음과 같습니다.

```text
late-progress: now_ms=10 elapsed_us=2000 required_deadline=10ms
result=0 fault=0 feeds=1 last_progress=10
```

Debug와 Release library에서 동일하게 재현했습니다. 현재 main과 같은 단일 worker descriptor `1ms/10ms/100us`에서도 확인했습니다.

```text
main-descriptor: completion_us=10100 deadline_ms=10
result=0 fault=0 feeds=1 last_progress=10
```

영향: 정상적인 callback 실행시간만으로 필수 worker의 deadline miss가 소거되고 IWDG refresh가 허용됩니다. 현재 차량 TX가 열린다는 뜻은 아니지만, T-102a가 검증해야 하는 progress/deadline watchdog 계약 자체를 위반하므로 P1입니다.

권고: step 누적 경과를 worker 시작·완료 판정에 반영하고, **이전 progress 기준 deadline 위반을 확인한 뒤** 새 progress/vote를 인정해야 합니다. 앞선 worker 지연, callback 도중 deadline 통과, late `OK`, wrap 조건을 회귀시험에 추가하십시오. 기존 BUSY 경계 시험과 높은 branch coverage는 이 경로를 검출하지 못합니다.

**Finding A-02 — P2 / OPEN: NMI fault latch 이후 진행 중이던 IWDG write가 실행될 수 있음**

위치: [core_hw.c:240](F:/dev/canview/firmware/communicator/stm32/platform/stm32g474/core_hw.c:240), 같은 파일 255–263행.

`canview_stm_watchdog_feed()`의 health 검사와 `IWDG->KR` 쓰기는 분리되어 있습니다. NMI는 fault를 latch하고 반환하므로 두 동작 사이에 발생하면 중단됐던 refresh가 계속 실행됩니다.

실제 Release ELF에서 확인한 순서입니다.

```text
08000758  bl   canview_stm_board_health
0800075c  cmp  r0, #0
0800075e  bne  failure
...
08000766  str  r2, [r3]     ; IWDG KR = 0xAAAA

NMI_Handler:
08000784  strb ...          ; hardware.fault = true
...
08000794  bx   lr           ; 중단 위치로 복귀
```

실패 시나리오: health 성공 후 `0x08000766` 실행 전에 CSS NMI가 발생합니다. NMI가 fault를 기록하고 복귀하면 IWDG가 한 번 더 갱신됩니다. 명령어 순서로 확인했으며 실제 보드 IRQ 주입은 **NOT_RUN**입니다.

영향: fault 이후 refresh 없이 reset을 기다린다는 계약에 틈이 있습니다. 이후 갱신은 차단되므로 무한 refresh나 TX 허용 결함은 아니며, reset 예정 시각이 뒤로 밀리는 제한된 영향으로 P2 판정합니다.

권고: terminal NMI가 중단된 feed 경로로 복귀하지 않도록 fail-stop/reset 정책을 정하고 이 경계의 시험을 추가하십시오. PRIMASK critical section이나 마지막 fault 재검사만으로는 NMI와 최종 write 사이의 경쟁을 제거할 수 없습니다.
