## Finding

### A-P1 — heartbeat timeout 뒤 fresh HELLO 없이 admission 재개 가능

heartbeat timeout으로 링크가 `OFFLINE`이 되어도 `hello_complete`와 `heartbeat_seen`이 남는다. 같은 boot id의 heartbeat가 다시 들어오면 fresh HELLO/ACK/safety snapshot 없이 `ONLINE` 및 admission 조건으로 돌아갈 수 있다. timeout은 세션 재동기화가 필요한 실패로 처리하고 HELLO/ACK부터 다시 요구해야 한다.

### A-P1 — stale command-cache slot index로 지연된 result가 새 command에 기록될 수 있음

`mark_ack`와 `record_result`가 slot index만 받는다. slot 만료 후 같은 slot이 새 command에 재사용되면, 지연된 이전 command의 result가 새 command entry에 기록될 수 있다. index만으로 entry identity를 표현하지 말고 generation/request token/command identity를 함께 검증하는 handle을 사용해야 한다.

### A-P1 — wire validation이 direction/auth/control admission을 보장하지 않음

`COMMAND_REQUEST` 검증은 token/TTL/suffix/reserved field 정도만 확인하며, direction과 peer role, 세션 인증, control lease, safety snapshot, hardware TX gate와 결합되지 않는다. CRC는 무결성 검증이지 인증이 아니다. T-004에 command dispatcher가 없더라도 semantic codec API가 wire validation 결과를 최종 admission처럼 오용할 수 없도록 별도 typed admission 경계와 명시적 caller contract가 필요하다.

### A-P1 — observer plan quota가 실제 예산·예약 없이 큰 정수를 허용함

`max_records`와 `max_bytes`가 큰 정수까지 허용되지만 플랫폼별 queue/메모리/CPU/ESP-NOW budget 또는 control queue reserve와 연결되지 않는다. observer/raw stream이 safety/control queue와 예산을 잠식할 수 있다. schema 상한 또는 runtime budget reservation으로 control path starvation을 방지해야 한다.

### A-P1 — boot/reset 변화가 cache와 plan을 원자적으로 invalidate하지 않음

`note_hello`는 boot changed를 반환하지만 command cache와 observer plan을 함께 무효화하지 않는다. `link_reset`도 link state만 초기화하며 caller가 cache/plan reset을 빠뜨릴 수 있다. 세션 epoch/reset API가 link, cache, plan을 함께 전환하거나 stale object가 admission에 사용되지 않음을 API로 보장해야 한다.

### A-P1 — ISR/task ownership과 동기화 계약이 mutable state에 강제되지 않음

cache, plan, link state를 어느 task/ISR가 소유하고 어떤 synchronization을 사용하는지 코드/API가 강제하지 않는다. UART physical DMA가 T-004 범위 밖이어도 shared mutable state의 owner contract가 없으면 ISR와 task가 동시에 갱신하는 통합에서 race가 발생할 수 있다. owner-only API 또는 명시적 lock/queue 경계를 문서와 interface에 넣어야 한다.

### A-P2 — observer plan digest를 실제 plan content와 재계산·대조하지 않음

BEGIN/CHUNK로 받은 canonical plan content와 COMMIT의 `plan_digest`가 일치하는지 codec이 계산하지 않는다. 임의 digest가 수락될 수 있어 동일 plan identity와 내용의 연결이 caller 신뢰에 의존한다. digest algorithm과 canonicalization을 정하고 COMMIT에서 대조해야 한다.

### A-P2 — target RAM/stack budget 근거 부족

command cache와 codec/plan context의 메모리 사용량이 target map/stack budget으로 검증되지 않았다. host test context의 큰 stack allocation만으로 STM32/ESP32 target 안전성을 주장할 수 없다. target size 및 stack watermark/map 근거와 compile-time budget assertion이 필요하다.

### A-P1-GATE — physical RTS/CTS와 100 ms/1 s timing gate 미검증

4 Mbps 8-N-1, RTS/CTS, 100 ms/1 s timeout 및 장시간 fault behavior는 physical target에서 검증되지 않았다. 이는 source-only test로 통과 처리할 수 없는 target gate이며, 관련 hardware/bench evidence가 생길 때까지 NOT_RUN으로 남겨야 한다.

## 잔여 불확실성

후속 dispatcher나 STM32 safety/lease wrapper가 direction/auth/control admission을 담당할 가능성은 있으나, 현재 T-004 immutable candidate 안에서는 확인되지 않았다. 해당 경계가 후속 task 소유라면 T-004 API가 codec validation을 final vehicle admission으로 오해하지 않도록 명시적으로 분리하고 후속 task를 추적해야 한다.
