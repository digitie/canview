### 정적 자원 기록 부족

위치: `shared/ota/README.md:323–351`.

문서의 산술은 일치한다.

| 구성 | 산술 |
|---|---:|
| 현재 receiver의 prefix + body + PSA | 16,488 + 856 + 108 = **17,452 B** |
| 향후 prefix + stage + PSA | 16,488 + 896 + 108 = **17,492 B** |
| 위 구성에 별도 16 KiB chunk 추가 | 17,492 + 16,384 = **33,876 B** |

Stage가 body를 포함하므로 중복 합산하지 않는다. Receiver의 실제 정적 선언도 `tests/fixtures/idf-ota-image/main/receiver.c:30–39`와 부합한다. 다만 크기 숫자 자체는 작성자가 기록한 Xtensa ELF/DWARF 값이며, 이번 리뷰에서 ELF를 재추출하지 않았다.

다음 상한은 소스와 대조했다.

- CBOR: 16 KiB, 2,048 items, depth 8; 고정 stack, 비재귀 순회.
- Manifest: 역할별 이미지 최대 2개, ABI 조합 최대 16개.
- Body: feed 최대 16 KiB, 이미지 경계에서 hash 종료·재시작.
- STM native: 최대 180 KiB, SHA256 최대 2회 및 P256 검증 1회.

함수 자체 frame과 전체 호출 stack을 구분하고, fixture stack 16,384 B를 실측 보증으로 표현하지 않는다. SDK 내부 heap을 0으로 가정하지 않으며 callback 지연을 portable core가 중단할 수 없다는 제한도 명시한다.

따라서 **정적 기록 부족은 해소되었다.** 전체 RAM 여유, SDK peak heap, stack high-water, WCET·watchdog 응답 보증까지 해결된 것은 아니다.
