# T-004 실제 바이트 계수 장기 시험

- 시험 코드 기준: `027b22e6e22997e5405cbbdaeb95545037c55625`
- production C 기준: `6dc2218`과 동일. 최종 `3c6967a`에서도 production C와 soak 함수는 변경되지 않았다.
- 실행 환경: Windows native, Clang23.1.0, CMake4.4.3, Ninja1.13.2, Release `-O3`
- 명령: `./build/host-release/canview-uart-tests.exe soak-24h`
- 시작: 2026-09-07 06:30:46 KST, 소요 801.8717662초, exit0
- 해석: 벽시계 24시간 시험이 아니라 4 Mbps·8-N-1 포화 회선의 24시간 바이트 수를 가속 처리한 C host 시험이다. physical UART·DMA·RTS/CTS soak가 아니다.

## 출력 원문

```text
SOAK progress actual_bytes=33120000127,34560000039
SOAK progress actual_bytes=34560000091,34560000039
PASS: C UART soak direction=0 seconds=86400 baud=4000000 bits_per_byte=10 required_bytes=34560000000 actual_bytes=34560000091 accepted=161183890 faults=161669
PASS: C UART soak direction=1 seconds=86400 baud=4000000 bits_per_byte=10 required_bytes=34560000000 actual_bytes=34560000039 accepted=152973141 faults=153434
soak_wall_seconds=801.8717662 exit=0
```

요구량은 방향당 `4,000,000 / 10 × 86,400 = 34,560,000,000 byte`다. 방향0은 CAN_RX_BATCH, 방향1은 CAN_OBSERVER_PLAN의 독립 codec context를 사용했다. 두 방향의 실제 합계는 69,120,000,130 byte, 정상 frame 합계는 314,157,031개, 주입 fault는 315,103회다.

## 통과한 assertion

- 각 입력 byte를 production `canview_uart_codec_feed`에 전달하고 실제 수를 계수했다. primary frame 10Hz의 가상시간 결과를 full-rate로 환산하지 않았다.
- data 변경·삭제·삽입·oversize burst를 번갈아 넣었다. 손상 frame은 `CANVIEW_OK`가 될 수 없으며 다음 정상 frame은 delimiter에서 복구했다.
- 정상 frame 수와 codec의 `packets_ok`가 일치했고, CRC/malformed/oversize counter의 합계가 각 방향 fault 수와 일치했다.
- 매 정상 frame 뒤 guard word가 유지되고 `stream.used == 0`, `discarding == false`였다. 마지막에도 잔여 입력이 없었다.
- production parser는 caller-owned 고정 버퍼를 사용하며 heap 할당이 없다. 이 full-rate 실행은 Release였고, 별도 ASan+UBSan 전체 68개 시험과 soak-smoke도 통과했다. full-rate 실행 자체에 sanitizer를 적용했다고 주장하지 않는다.

물리 장치 uptime, 실제 interrupt latency, 4 Mbps 전기 파형과 CAN/RF 간섭은 T-104/T-202/T-500 후속 gate다.
