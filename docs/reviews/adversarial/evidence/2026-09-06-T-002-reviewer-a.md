## 최초 관찰 — `9cff518`

실행한 generator/check·host test를 확인한 뒤 다음 finding을 기록했다.

### P1

- singleton TLV가 중복되어도 oracle이 허용하고, known base type에 critical bit를 붙인 미등록 probe도 허용한다. unknown critical과 singleton 정책이 실제 decode 경로에 닫히지 않았다.
- pairing canonical/HMAC 입력에서 `DISCOVERY.expires_at_ms`, `PAIR_REQUEST.request_token`와 `PAIR_REQUEST.expires_at_ms`가 빠져 있어 transcript freshness·request binding이 wire field와 일치하지 않는다.
- command argument/session binding이 불완전하다. malformed command argument TLV가 허용되고, header `session_id`와 command payload `wireless_session_id` 불일치가 허용된다.
- message authorization/state/version semantics가 metadata-only다. 잘못된 role/priority, HELLO broadcast, session, minor 관련 probe가 oracle에서 거부되지 않는다.

### P2

- resource/range/cross-field 검증이 부족하고 bulk `payload_len`과 suffix 길이의 불일치를 허용한다.
- Bridge/config/bulk 경계가 선언에만 있고 encoder/wire owner binding 또는 runtime 경계에 소비되지 않는다.
- `CAN_FILTER_GET` ABI와 문서/contract 의미가 일치하는지 닫힌 gate가 없다.
- Windows generator gate는 checkout CRLF에서 schema digest가 달라질 수 있다.
- C packed ABI compile gate는 reviewer 환경에서 `NOT_RUN`이었다.

최초 verdict는 P1이 닫히지 않아 `BLOCK`이다.
