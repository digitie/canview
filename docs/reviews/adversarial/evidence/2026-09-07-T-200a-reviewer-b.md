## 5. Finding 외 공격·확인 사항

- pool capacity 1–16, 256B 경계, exhaustion, output 보존, context/data/output alias, cross-pool·double·stale release를 검토했다.
- copy/release/stats와 generation 갱신은 동일 lock 아래 수행된다. 최대 generation slot의 retire로 wrap 재사용을 막는다.
- 4-thread/2-slot 시험은 총 8,000 payload를 검증했다. 이를 ESP32 dual-core scheduling 증거로 취급하지 않는다.
- core의 이전 진척 deadline, 실행 budget, backward/frozen clock, callback 재진입·첫 fault 보존, feed 실패 후 terminal 상태를 검토·시험했다.
- 실제 adapter의 owner 검사, 등록 중복·SDK 오류, critical 진입 후 clock 재검사, delay-until 실패·tick wrap 시험을 확인했다.
- IDF 원문에서 stack watermark의 byte 단위와 PSRAM ECC 가용량 계산을 대조했다.
- app의 각 boot 실패와 wait/late 실패에서 추가 feed 없이 idle에 도달하는 시험을 실행했다.
- sense 값은 진단으로만 사용된다. UART/radio/OTA/NVS application write나 차량 TX 시작 호출은 이번 실행 경로에서 발견하지 않았다.
- default GPIO 안전과 reset/brownout 전기적 안전은 별개다. 외부 gate·pull과 실물 계측의 필요성을 유지한다.
